# Kareocar 開發順序與驗收清單

日期：2026-09-23｜依據：PRODUCT_SPEC.md v1.0｜狀態：後續執行計畫，本輪未啟動開發

## 1. 執行原則與協作

- 每項工作對應需求 S01–S11、基準 commit、修改負責人、驗收證據與未解問題。
- 沿用版本庫 CLAUDE.md：Claude 主要開發與測試，Codex 技術審查／明確交辦問題，Gemini 情境整理及流程驗收，使用者決定需求與最後驗收。
- 每項只一位程式修改負責人；換手先交接。不因本文件而自動建立任務、派發代理人或啟動其他模型。
- 涉及前端/API/資料庫契約時同步檢查相依層；純文件不更動應用。
- 程式碼靜態推導、實際測試、正式環境確認分開標示。演示資料、mock、成功頁或通知佇列均不等於正式成功。
- 授權內可做文件與唯讀核對；部署、正式資料庫寫入、安裝依專案規則另處理。本階段不做這些動作。

## 2. 分期與交付條件

| 工作 | 依賴 | 範圍 | 階段完成標準 |
| --- | --- | --- | --- |
| T00 基準與環境 | 無 | 核對最新 commit、部署狀況、隔離測試環境、資料庫角色及外部待辦 | 確認測試不會寫正式庫；建立外部 G01–G06 證據清單 |
| T01 身分與權限 | T00 | 三社群＋手機、乘客關係、居服機構／個案、各角色授權及業者資格模型 | A01–A03、A13 通過；外部登入先沙盒，再正式驗證 |
| T02 地點與預約 | T01 | 全雙北醫院、別名、院區入口、分段時間、批次回診與下次接送 | A04–A06 通過，位置與未知時間不被虛構 |
| T03 接案與派車 | T01/T02 | 後端資源／版本一致性、推薦、2 小時、近程指派、改單及交接 | A07–A09 通過，含真實資料庫併發證據 |
| T04 執行與異常 | T03 | 司機流程、政府等候、離線、證明、站內通知／電話、撤權 | A10–A13 通過 |
| T05 補助與車資 | T01/T02，可與後續設計銜接 | Gemini 來源擷取、版本、個案查核、行前同意及完成後確認 | A14–A15 通過；有效方案版本具官方依據 |
| T06 訂閱及帳務 | T04/T05 | 計費帳本、預付月費／5%、看板、轉帳、綠界、爭議與結清 | A16–A20 通過；真實收費須 G01–G03 完成 |
| T07 保存與完整驗收 | 各資料模型穩定；保存設計自 T01 開始 | 分類保存、刪除／備份、安全與全角色易用性 | A21–A23 通過，外部門檻清楚處置 |

上述為工作相依，不代表允許安全、授權或保存規則延後補；各模組開發時即納入。三家社群均為第一版必要項，不因單一供應商設定未完就縮減承諾。

## 3. 可操作的驗收案例

所有案例目前均為「待執行」，歷史離線測試不自動勾選。每次測試記錄 commit、環境、輸入、實際結果與證據；涉及個資採測試資料。

| ID | 情境與操作 | 預期結果 |
| --- | --- | --- |
| A01 | 分別 Google／Facebook／Apple 登入，綁定新手機；嘗試綁既有手機、錯誤或過期 OTP | 三家均真實成功；既有帳號先驗證，不依 email 合併，不跨人轉移資料 |
| A02 | 家屬新增家人、申請連結既有乘客；未同意時用 API 查詢，再同意／撤銷 | 未授權查不到；權限分粒度；撤銷立即阻止新存取與代約，既有行程交接 |
| A03 | 居服員受邀驗手機、取得一位個案授權；查另一位個案；離職停用 | 僅已授權個案可見，代約不含費用同意等額外權限；離職交接不取消接送 |
| A04 | 搜台大／臺大／台大醫院，選同院區及不同院區／入口，輸入不明地址 | 同地點共用 ID，不同院區不合併；歧義必選，未確認地址不可直接排車；官方醫院清單逐筆比對有涵蓋率 |
| A05 | 去程有時間、回程未定；反過來；兩段皆未定；單程未填 | 前兩者可送並有警告；後兩者拒絕；未知段不顯示已安排或啟動倒數 |
| A06 | 建固定回診跨預約開放期，再從上次行程預約同一天 | 可預約期逐趟建立，超期草稿、不自動送；重複提示／阻止重複建立；看診時間不冒充上車時間 |
| A07 | 兩組織同時搶同案；兩案搶同一司機車輛；建議後案件被修改；重送請求 | 僅有效承接成功，資源不重疊，舊版本拒絕重算；後端交易與重送均不產生雙接／雙派 |
| A08 | 距上車 >2h 與 ≤2h 分別承接；用模擬時鐘推進 1h／2h；未定段補時間 | 遠程 1h 提醒、最遲 2h 指派；近程接案即指派且可抵達；逾期通知及交接，不自動取消，未定段補齊才起算 |
| A09 | 已承接申請改時地或拆段，業者尚未同意／同意／拒絕；司機無法執行 | 等待與拒絕時舊安排有效；同意重驗資源再更新；改派確認新責任者、通知、撤舊權限 |
| A10 | 司機早到、遲到、錯入口、正常到但乘客未到 | 紀錄抵達及聯絡，按方案等候與確認；不錯扣乘客等待時間、不倒數自動判罰、不標完成、不計 5% |
| A11 | 斷線完成、重連多次上傳；離線期間被改派；服務照片另一裝置查看 | 不重複執行／計費，衝突可處理；原司機不可越權寫回；必要服務證明依保存方案可取回 |
| A12 | 觸發改派／取消，使用者未讀通知；調度記錄打電話未接／接通 | 站內狀態不冒充已收到；電話人員、時間、對象、結果可追蹤 |
| A13 | 承接前查需求 API／備註／匯出，承接後查執行，退單後查快取；資格過期仍嘗試接案 | 未洩漏敏感欄位；執行僅必要人員；撤權後新存取受阻及快取清理；過期拒新接案、既有妥善交接 |
| A14 | Gemini 擷取有缺漏／互相矛盾文件，發布新規則，再查看舊報價 | 不直接發布錯誤；有原文及來源日期、生效日、版本；適用組織同步，舊金額不變，個資不送 Gemini |
| A15 | 補助資料查不到；平台估額與官方不同；有代約權但無費用權；完成後費用有爭議 | 顯示待確認不自動自費；來源分開；無權不能同意；行前同意與最終確認分開，未確認不計費 |
| A16 | 9/30 完成、10/2 確認；去程完成回程取消；重複完成；政府款未入帳 | 10 月累積／11 月請款，只計已完成確認段一次；不以政府入帳延後；預估與本期到期額分開 |
| A17 | 首次轉帳只傳截圖、實際入帳；續期轉帳與刷卡回呼同時到；回呼重送／偽造 | 截圖不開通，核實資格及款項後開通；同帳不雙收，伺服器驗證及去重，有完整對帳 |
| A18 | 10 日扣款失敗／未知／需驗證；13 日重試；15–16 日；事前撤銷授權 | 只對可重試且確認失敗一次重試，未知先查；撤銷不扣；無爭議逾期才限制新增，既有可執行 |
| A19 | 出帳後退車資 200，同時提交更正；取消訂閱並有溢付 | 只調整平台費 10 一次、保留原帳單；下期月費不再累積，結清與退款不要求續訂 |
| A20 | 扣款前／後爭議，部分爭議駁回；查看費用看板與另一組織帳單 | 暫緩爭議部分、不重複扣；無爭議款正常；駁回另給期限；費用分類正確且不可跨組織查閱 |
| A21 | 推進至各保存邊界，設置限縮爭議保留，再還原刪除前備份 | 90／180 天、1 年與30 天備份按定義處理；必要法定證據不誤刪，僅保留相關爭議資料，還原重套刪除 |
| A22 | 家屬與居服員各自完整送單→業者接案→司機完成→車資確認→帳務 | 每個角色可直覺找到下一步，狀態一致；無需內部技術說明才能操作 |
| A23 | 合法個人業者兼負責人／司機，跑完整資格→訂閱→承接→執行→對帳 | 簡化介面仍同等執行資格、容量、時間、付款與權限檢查 |

## 4. 上線檢核與剩餘決策

- 核心案例 A01–A23 需有實測證據；失敗或未測不得標完成。
- SQL/RLS 變更用 repo 隔離 PostgreSQL CI 或已確認隔離本機環境驗證，不能只靠前端測試。
- 外部門檻 G01–G06 要有證據與適用範圍；若功能依法尚不能啟用，明確限制並由使用者決定是否符合交付期待，不自行宣布完整交付。
- 在 T06 設計時集中決定帳期邊界、取整、爭議補繳期限等會改變費用／承諾的參數，未定前測試標資料待補，不任填預設當商業決策。
- 真實金流先完成官方測試環境驗收與核准確認；正式收費、部署另依授權執行。
- 完成度表隨每次交付更新，附測試及 commit；不再把需求草稿加章節當作功能實作進度。

## 5. 後續交接格式

每項任務交付：需求 ID、負責人、基準與最新 commit／PR、修改範圍、實測案例與結果、未解外部條件、下一位需要檢查的內容。重要改動由 Codex 依同一 commit 審查；Gemini 的流程驗收與產品中 Gemini 擷取 API 是不同工作，不混為已整合。
