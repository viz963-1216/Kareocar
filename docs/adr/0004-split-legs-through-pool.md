# 跨機構排車：來回預約拆段走需求池，不由平台指定機構

來回預約的其中一段（去程或回程），承接機構可以退回需求池，由別家接送機構接案成為那一段的協力機構。前提是需求者預約時同意分段載送（預設勾選）。每筆預約一定有一家承接機構，它是需求者的主要聯絡對象；協力機構只負責、也只看得到自己那一段，以及服務對象與聯絡資料。承接機構退回自己那段時，協力機構升格為承接機構。原本「平台管理者把某一段指定給別家機構」的功能拿掉：被指定的機構在資料庫權限下讀不到那筆預約，從來沒辦法真的排車。

## Considered Options

- 平台管理者指定機構：要平台人工介入，被指定的機構也沒有機會先同意
- 承接機構直接轉給特定機構：要另外做「邀請／接受」的流程與合作名單，需求池已經提供「對方同意才算數」
- 需求池一開始就把每一段分開列、各自接案：可能出現兩家各接一段、沒有人對整筆負責，需求者不知道找誰

## Consequences

- 預約的存取不再只看預約的承接機構：協力機構要能讀到預約的部分資料，退回後立即失去存取
- 需求池、接案期限、通知、長照特約與補助資訊都要能以「一段」為單位運作
- 一趟行程仍只屬於一家機構，不做兩家機構的車共乘同一趟
