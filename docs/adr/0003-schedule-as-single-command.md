# 排車是一個 command、一筆交易；狀態規則前後端共用一份

前端原本是改完整份資料後，把預約、行程、事件分到不同端點、各自一筆交易送出；行程那一步失敗時，伺服器上會留下「已排車卻沒有行程」的預約。現在排車（從預約建立行程、套用排車建議）一律送 `v2-schedule-trips`，在一筆交易內寫入行程、預約、事件，任何一筆不合規則就全部不寫入；預約排車後的樣子由伺服器計算，前端送來的預約內容不採用。預約與行程的狀態轉換、排車規則放在 `js/lifecycle.js`，瀏覽器與 Netlify Functions 載入同一個檔案。

## Considered Options

- 保留分段寫入、在伺服器補檢查：檢查再多也擋不住跨交易的半套狀態
- 把排車規則搬進 Postgres 函式：規則會變成 SQL 與 JS 兩份，正是要消除的重複

## Consequences

- 排車需要網路（離線時拒絕），因為伺服器要確認司機、車輛、預約都還可用
- 之後預約與行程搬到正式資料表（#43）時，沿用「意圖形狀的 command」，不要回到「整筆紀錄差異」的寫法
